# 用户自己配音

正式成片的声音是用户自己录的。你出台词本、导入录音、看回读结果；读音和语气的最终判断交给用户人耳（你听不到声音）。合成声只当草稿用，见第 6 节。

## 1. 写台词时就防读错

- 多音字（长 zhǎng / cháng、重、发、行、处、血、量、便、泌、曲、着、得、为、几…）在 `lines[].say` 里写成无歧义的同音字，例如原文“一天长一点”，`say` 写“一天涨一点”；字幕永远用原字。台词本会把这个字的读音标出来。全片通用的替换写进 `design.say_overrides`（如 `{"长大": "涨大"}`）。
- 医学生僻字（潴 zhū、剜 wān、睾 gāo）在台词本里会自动带拼音提示；不放心的在 `say` 里写同音字。
- 数字、百分比、单位按要读的样子写进 `say`（“97%”→“百分之九十七”）。
- 旁白语速约每秒 4.5 字，宁慢勿快（中老年观众）；`voices[who].desc` 写清嗓音和语气要求。

## 2. 台词本

`python $P voice <专题>`（第一次跑会因为没有录音停在退出码 6）生成 `audio/台词本.md` 和 `audio/台词本.docx`：按角色分组，每句一行，含文件名、台词、读音提示、语气、参考时长，开头有录音要求。把 Word 版交给用户（可以直接打印或发给配音的人）。

## 3. 录音怎么放

全部放进专题的 `audio/recordings/`，格式随意（m4a、mp3、wav、aac、flac、ogg、手机录音、视频文件都行）。四种放法，同一句以前面的为准：

| 放法 | 文件名 | 说明 |
|---|---|---|
| 一句一个文件 | `s03_2.m4a` | 台词本第一列；重录某一句也用这个，会覆盖整段文件里的那一句 |
| 某场某角色一个文件 | `s03_laozhang.m4a` | 这一场该角色的台词按顺序读，句间停 1.5 秒以上 |
| 一场一个文件 | `s03.m4a` | 这一场全部台词（所有角色）按顺序读 |
| 一个角色一个文件 | `narrator.m4a` | 该角色全片台词按台词本顺序读 |

整段文件按最长的停顿切句：句间停顿太短（< 0.5 秒）会提示“分句可能不准”，回读核对会把切错的句子揪出来。读错了停 2 秒重读整句也行，但多出来的那遍会让切句错位，最稳的是读错的句子单独录一个文件。

## 4. 导入做了什么

再跑 `python $P voice <专题>`：

1. 转 48 kHz 单声道、去 70 Hz 以下低频、轻度降噪；
2. 切掉首尾静音（留 80 ms）、句中超过 0.4 秒（旁白）/ 0.35 秒（角色）的停顿压短、停顿处压底噪；
3. 响度统一 −16 LUFS，限幅，首尾淡入淡出；
4. whisper 回读（模型 large-v3-turbo，CPU 运行；机器慢可在环境变量 `KEPU_ASR_MODEL` 设 `medium` / `small`）；
5. 和台词比：无调拼音相似度 ≥ 0.92（`tts.min_pinyin`）、长度比 0.88–1.15、关键词（`tts.must`）都在，才算过；
6. 逐字起止时刻（whisper 词级时间 + 用波形停顿校正；装了 torch + torchaudio 时改用 MMS_FA 强制对齐，`setup --align`）。

输出每句一行：`OK` / `xx`、拼音相似度、长度比、字/秒、时长、回读文字、问题说明。已处理的句子按录音文件缓存，只换了某几句就只重做那几句；`--reimport` 全部重做。

## 5. 回读没过怎么办

- 回读文字和台词是同音字差别（“寒战”回读成“寒颤”）：拼音相似度不受影响，一般能过。
- `多读或漏读`、`和台词对不上`：多半是读错、漏字、加字，或整段文件切句错位。让用户听这一句（`audio/lines/<id>.wav`）：
  - 读得没问题（whisper 认错了）→ 把 id 写进 `storyboard.tts.ear_confirmed`；
  - 确实读错 → 单句重录 `<id>.m4a` 放进 `audio/recordings/` 再导入。
- `多了语气词`：用户口头加了“啊、呃”，字幕里没有。轻微的可以人耳确认放过，明显的重录。
- `语速偏快`：超过 5.6 字/秒，建议重录慢一点。
- 读音（声调、多音字）whisper 常查不出：“长 cháng / zhǎng”两种读音它都写“长”。所以重要的多音字要靠台词本提示 + 用户自己听。

## 6. 录音之后

`timeline` → `mix` → `frames` / `animatic`。改了台词文字就要重录那一句（台词和录音对不上，回读会报出来）。字幕时刻吸附波形开口点，QA 门要求 ≥ 95% 的字幕块起点与开口点相差 ≤ 100 ms。

## 6. 草稿配音（可选，只为先看节奏）

用户还没录音、又想先看带声音的预演时：

1. 先问用户：草稿配音用微软 Edge 的在线朗读服务，台词文本会发到这个服务，是否同意。不同意就用 `timeline --estimate` 出无声预演。
2. 同意后 `python -m pip install edge-tts`，再跑 `python $P voice <专题> --draft`（要联网）。没有录音的句子会用合成声顶上，文件在 `audio/draft/`；已有录音的句子仍用录音。
3. 草稿声只够出预演（`animatic`）。预演审核、S6a 确认、正式渲染都会停在退出码 6，提示先导入真人录音。合成声的读音、停顿、时长都和真人不一样，按它确认的节奏不算数。
4. 用户录好后照常放进 `audio/recordings/` 再跑 `voice`，草稿自动被录音替换；全部句子都有录音后，流水线才往下走。
5. 想换草稿音色：`voices[who].draft_voice` 写 edge-tts 的音色名（如 `zh-CN-YunxiNeural`）。
